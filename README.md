## 🤔 왜 필요한가요?

노트북으로 작업하다 보면 이런 순간이 반복됩니다.

| 궁금한 것 | 예전엔 | 이제는 |
|---|---|---|
| 지금 무슨 노래지? | 플레이어 창 찾기 | 시선만 위로 |

**시선만 위로 옮기면 답이 나오게.** 그게 TopDock의 전부입니다.

## ✨ 기능

### 🎵 미디어 컨트롤 & 실시간 가사

- **모든 플레이어 지원** — 브라우저 YouTube, Spotify, PotPlayer 등 SMTC를 보고하는 앱이라면 무엇이든
- 앨범아트 · 진행바 · 재생/일시정지/이전/다음 컨트롤
- **싱크 가사 자동 검색** ([LRCLIB](https://lrclib.net/)) — 지금 재생 구간 가사가 노치에 흐릅니다
- 영상과 음원 길이가 달라도 **오프셋 자동 보정**으로 싱크 유지
- 한 번 본 가사는 **디스크에 영구 캐시** — 오프라인에서도 즉시 표시
- 재생 중엔 노치 테두리의 빛이 **앨범 지배색**으로 물듭니다

### 🤖 AI 비서

> [!NOTE]
> 노치 오른쪽의 AI 아이콘을 누르거나 **<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Space</kbd>** 로 부릅니다.
> 생각하는 동안 노치 안의 **눈(AiFace)**이 상태를 표정으로 보여줍니다.
> 지시를 보내면 화면은 스스로 접히고 진행 상태가 노치 알림으로 이어집니다 — 실패했을 때만 자동으로 다시 펼쳐집니다.

명령이 아니라 **행동**까지 합니다 — 모델이 도구를 직접 호출합니다.

| 도구 | 하는 일 |
|---|---|
| `media_play_pause` / `media_next` / `media_previous` | 재생 제어 — "다음 곡" |
| `media_seek` | 재생 위치 앞뒤 이동 — "30초 앞으로" |
| `set_volume` | 시스템 볼륨 설정 — "볼륨 30으로" |
| `open_app` | 허용 목록의 앱 실행 — "메모장 열어줘" |
| `open_url` | 브라우저로 URL 열기 |
| `play_youtube` | 유튜브 검색 후 첫 영상 재생 |

- **키 없이 바로 사용** — 기본 프로바이더 LLM7(분당 30회 무료)
- 프로바이더 선택: LLM7 · Google Gemini · OpenRouter · Upstage Solar · **Ollama(로컬)**
- **실행 허용 목록** — 설정에 적힌 앱만 실행합니다. 한글 별칭(`메모장`·`계산기`·`크롬`)은 자동 번역
- 프롬프트 인젝션 방어 — 이름 그대로 실행하지 않고 항상 허용 목록으로 검증
- **진행 단계 9종을 얼굴로** — 도구 이름을 작업(궤도) · 검색(구체) · 추론(큐브) · 청취(파동) · 연결(네트워크) · 직조(꼬임) · 작곡(리본) · 대기(링) · 변형(모프)으로 옮기고, 노치 안의 눈이 그 단계를 표정(집중 · 사고 · 발화)으로 말합니다. 읽을 답이 화면에 남아 있는 동안엔 눈이 멈춥니다 — 글 옆에서 계속 깜빡이면 시선을 뺏깁니다

### 📋 클립보드 히스토리

- 복사하면 노치 안쪽에 작은 **타일 하나가 잠깐 스며들고 테두리 빛이 한 번 밝아집니다** (떠 있는 창 없음) — 알림의 앱 타일과 같은 모양·같은 자리
- **<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>V</kbd>** 또는 **노치 클릭**으로 최근 **5개 목록**이 노치 아래에 내려옵니다
- 텍스트 · **Win+Shift+S 캡처 이미지(썸네일)** · **탐색기에서 복사한 파일**까지 한 목록에서 처리
- 항목을 클릭하면 **클립보드에 올림과 동시에 직전 창에 바로 붙여넣습니다** (Ctrl+V 주입)
- **한 줄 한 줄이 같은 언어** — 항목 왼쪽에 정체성 타일이 앉습니다(글자 `텍` · 파일 `파` · 캡처는 그림). 알림 카드의 앱 타일과 같은 22px 둥근 사각형이라, 어느 화면이든 왼쪽 한 줄이 눈의 기준이 됩니다
- **<kbd>↑</kbd><kbd>↓</kbd>** 이동 · **<kbd>Enter</kbd>** 붙여넣기 · **<kbd>Delete</kbd>** 삭제 · **<kbd>Esc</kbd>** 닫기 — 마우스 없이도 조작
- 행의 **✕**로 개별 삭제, 헤더 우측 휴지통으로 **전체 삭제**
- 같은 내용을 여러 번 복사/재캡처해도 **중복 없이 한 장만** 유지

### 🔔 노치 알림

노치는 같은 통로 하나로 모든 일을 알립니다.

- **지시하면 노치가 스스로 접혀서 일합니다** — 비서 화면이 저절로 닫히고, 노치가 진행 상태를 대신 보여줍니다
- **진행 중엔 계속 떠 있습니다** — "AI · 생각 중…" · "실행 · 볼륨 조절 중…"이 끝날 때까지 자리를 지킵니다 (깜빡였다 사라지지 않음)
- **완료되면 딱 한 번** — "AI · 완료"가 잠깐 떴다가 사라집니다
- **실패했을 때만 화면으로** — 응답을 못 받으면 비서 화면이 다시 펼쳐져 오류를 바로 보여줍니다
- 진행 중에 핫키를 다시 누르면 화면을 펼쳐 상태를 볼 수 있고, 거기서 **Esc**로 취소합니다
- **Windows 알림** — 앱 타일(이름 첫 글자, 파랑) + 앱 이름 + 제목 — 앱이 누가 말하는지 먼저 보여줍니다
- **복사** — 화면을 가로채지 않고 조용한 타일 + 테두리 빛 한 번
- 알림이 뜨는 순간 노치 테두리가 한 번 밝아집니다
- 상자가 먼저 자리를 만들고 글자가 조금 늦게 미끄러져 앉습니다 — 빈 카드에 글자가 툭 박히지 않습니다
- **같은 손짓이 화면을 넘어갑니다** — 클립보드 기록도, 볼륨 링도, 비서 카드도 같은 순서로 앉고 같은 방향으로 물러납니다. 화면마다 다른 리듬으로 움직이면 앱이 아니라 기능 모음처럼 보입니다

### 📬 알림 인박스

노치 알림은 5초 뒤 스스로 걷히고, 새 알림이 오면 앞의 것을 밀어냅니다. 잠깐 자리를 비운 사이에 온 알림을 되찾는 곳입니다.

- **<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>** 또는 트레이 아이콘 우클릭 → **알림 기록**(안 읽은 개수가 함께 표시됨)
- 방금 뜬 Windows 알림을 **클릭하면 그 알림의 기록**으로 이어집니다
- **한 번에 한 건씩** — 숫자(`2 / 7`)와 함께 앱 타일 · 출처 · 언제 · 제목 · 본문을 노치 카드에 그대로 다시 보여줍니다
- 넘길 때는 내용이 **방향대로 미끄러집니다** — 글자만 갈아끼우지 않습니다
- **<kbd>↑</kbd><kbd>↓</kbd> · 마우스 휠 · 클릭**으로 넘기고(끝에서 순환), **<kbd>Delete</kbd>** 삭제 · **<kbd>Esc</kbd>** 닫기 · 휴지통으로 전체 삭제
- 최근 **40건**까지 기억하고, 열어 둔 채 새 알림이 오면 **읽던 건은 그대로** 두고 최신만 위에 쌓입니다
- 노치 알림 표시를 꺼 두었어도 **기록은 계속 남습니다** — 알림을 보는 조용한 통로

> [!NOTE]
> 인박스를 보는 동안에는 마우스 휠이 **볼륨 대신 기록을 넘깁니다**.

### 🖥️ 여러 모니터

노치가 앉을 화면을 설정에서 고를 수 있습니다 — `주 모니터 (자동)` 또는 특정 디스플레이.

- **주 모니터가 (0,0)에 없어도 제자리** — 예전에는 창 위치를 `Left = 0` + 주 화면 폭으로 못 박아 두어서, 주 모니터를 오른쪽이나 아래에 두고 쓰는 배치에서는 노치가 엉뚱한 화면에 앉았습니다(모니터를 고를 수 있게 하는 것과는 별개의 버그였습니다). 이제는 고른 모니터의 실제 사각형을 그대로 창에 씌웁니다
- **배율이 달라도 어긋나지 않게** — 좌표는 장치 픽셀로 넘기고(창이 덮는 공간과 모니터 목록의 공간이 같습니다), DIP로 적힌 상단 여백만 그 모니터의 배율로 환산합니다(175% 노트북에서 4px → 7장치 px)
- **모니터가 빠지면 물러섭니다** — 고른 모니터를 뽑으면 주 모니터로 옮겨 앉고 로그에 한 줄 남깁니다. 노치가 화면 밖으로 사라지는 일은 없습니다
- **구성이 바뀌면 따라갑니다** — 디스플레이를 붙이거나 빼면 Windows의 디스플레이 변경 알림을 받아 자리를 다시 계산합니다
- 어느 화면에 앉을지는 **화면 없는 순수 로직**(`TopDock.Logic/MonitorLayout.cs`)이 정합니다 — 주 모니터가 오른쪽에 있는 배치·왼쪽으로 뻗은 음수 좌표·세로 쌓기·사라진 모니터를 합성해 테스트가 잠급니다
- **아직 선명하지는 않습니다** — 배율이 다른 두 번째 모니터에 앉으면 위치와 크기는 맞지만, 앱이 `SYSTEM_AWARE`라 Windows가 창을 비트맵 확대해 그 화면에서는 흐릿합니다(per-monitor DPI 인식이 따로 필요합니다)

### 🔋 시스템 인디케이터

- 노치 우측 **상태 점** — 충전 중 = 초록(은은한 맥동), 저전력 = 빨강
- 노치 위에서 **마우스 휠만으로 볼륨 조절** + 실시간 볼륨 HUD
- 볼륨을 만지는 동안에도 확장 카드의 안쪽 빛은 **살짝 낮아질 뿐 꺼지지 않습니다** — 볼륨 링이 앨범색에 묻히지 않게 하면서 카드의 분위기는 지킵니다(끄면 빛이 통째로 사라져 고장처럼 보입니다)
- Windows 알림을 노치 위에서 접수
- 오른쪽 끝 **한 자리** — 평소엔 비어 있고, 음악이 흐르면 링이 상주하며 그 안에서 지금 나는 소리가 세 칸으로 살아 움직입니다

### 🔊 소리를 그리는 계기 (진짜 레벨)

접힌 노치에서도 펼친 카드에서도 같은 자리, 우측 상태 점 자리의 **링 하나**가 소리를 말합니다.

- 링 안의 세 칸은 장식이 아니라 **지금 나는 소리**입니다 — WASAPI 루프백으로 출력 파형을 되받아 직접 FFT(저 60–250 · 중 250–2000 · 고 2000–12000Hz). 조용한 구간에선 바가 내려앉고, 심벌이 터지면 오른쪽 칸이 뜁니다
- 밴드는 Hz로 정합니다 — 장치가 44.1kHz든 96kHz든 같은 소리는 같은 칸을 켭니다
- **바늘은 상태를 이기지 못합니다** — 배터리·AI 점이 뜨면 바늘만 비켜서고 호는 남습니다(점의 후광이 링의 빈 자리를 거의 다 채워 같이 그리면 겹칩니다). 규칙은 [`TopDock.Logic/AudioSlot.cs`](TopDock.Logic/AudioSlot.cs) 한 곳에
- 캡처를 못 열어도 링은 그대로 — 바늘 없이 호만 그립니다. 계기가 없다고 볼륨 UI가 사라지면 안 됩니다
- 순수 계산(분석기 · 어택/릴리즈)은 화면 없이 테스트합니다 — 100Hz 사인은 왼쪽 칸, 6kHz는 오른쪽 칸, 직류는 소리가 아님

### ✨ 살아있는 가장자리 (Living Edge)

노치 테두리는 장식이 아니라 **상태를 말하는 언어**입니다.

- **색** — 평소엔 중립 화이트, 음악이 재생되면 그 곡의 색
- **운동** — 대기(느리게) · 사고(크게) · 스트리밍(얇게) · 재생(크게 빠르게)
- **순간** — 복사 같은 이벤트에 테두리가 한 번 밝아짐
- 링 세그먼트마다 알파를 직접 계산해, 펼침/접힘 모프 중에도 빛이 튀지 않습니다

### 🎨 시각 값은 한 곳에

같은 타일인데 화면마다 크기가 다르거나, 같은 배지인데 모서리 반경이 다른 일은 **값을 화면마다 적어서** 생깁니다. 실제로 클립보드 타일 글자는 11, 같은 22px 알림 타일 글자는 12였고, 목록이 정착하는 시간은 클립보드 200ms · 알림 220ms로 갈라져 있었습니다.

이제 숫자는 [`TopDock.Logic/Tokens.cs`](TopDock.Logic/Tokens.cs)에, WPF 타입(CornerRadius·Brush)과 색은 [`DesignTokens.cs`](DesignTokens.cs)에 모아 두고, XAML은 `x:Static`으로 그 값을 읽습니다. **한 값을 고치면 알림 · 인박스 · 클립보드 · 볼륨 링 · 비서 카드가 함께 따라옵니다.**

- **숫자만 순수 로직에** — Tokens는 WPF를 참조하지 않으므로, 값 사이의 관계(제목 > 본문 > 출처, 퇴장 < 등장, 반경은 크기에 비례)를 창 없이 테스트로 잠글 수 있습니다
- **문자열 키가 아니라 컴파일되는 이름** — 오타를 내면 빌드가 깨집니다. 화면이 조용히 어긋나는 일이 없습니다
- **공용 규칙까지** — 애니메이션 60fps 같은 규칙도 같은 곳에서 한 번만 정합니다

## 🧩 기술 스택

| 영역 | 사용 기술 |
|---|---|
| UI | WPF (.NET 10) + 커스텀 애니메이션 |
| 글꼴 | [Pretendard](https://github.com/orioncactus/pretendard) (SIL OFL 1.1, 리소스 번들) |
| 미디어 감지 | Windows SMTC (`GlobalSystemMediaTransportControlsSession`) |
| 볼륨 | Core Audio COM (`IAudioEndpointVolume`) |
| 소리 계기 | WASAPI 루프백(`IAudioClient`) + 직접 쓴 FFT — 라이브러리 없이 |
| 배터리 | `SystemInformation.PowerStatus` |
| 가사 | [LRCLIB](https://lrclib.net/) API + LRC 파서 |
| AI | OpenAI 호환 SSE 스트리밍 + function calling |
| videoId 검색 | YouTube Data API v3 / HTML 폴백 |
| 시각 값 | `TopDock.Logic/Tokens.cs`(숫자) → `DesignTokens.cs`(WPF 타입) → XAML `x:Static` |

### 🧪 테스트

```bash
dotnet build
dotnet test tests/TopDock.Tests/TopDock.Tests.csproj
```

거의 모두 **화면 없이** 도는 순수 로직 테스트입니다(`TopDock.Logic`). 하나만 예외로 진짜 앱을 띄웁니다 —
**설정을 적용한 뒤에도 전역 단축키가 살아 있는지**. 핫키는 창에만 걸려서 안에서 확인할 수 없으므로,
앱이 `--selftest-hotkeys`로 잠깐 서 있고(창이 서면 READY, `apply`를 받으면 설정 창의 '적용'이 부르는
바로 그 경로를 돈다) 테스트가 **다른 프로세스에서** 그 조합을 잡아 봅니다. 적용 전에도, 적용 뒤에도
잡히지 않으면 그 단축기는 죽은 것입니다. 그래서 이 테스트만은 실행 중인 TopDock을 닫은 뒤에 돌려야 합니다
(둘은 같은 전역 핫키를 쥘 수 없습니다).

## 🗺️ 로드맵

### 최근 완료

- [x] 소리 계기 — 링 안의 세 칸이 장식이 아니라 실제 소리(WASAPI 루프백 + FFT)를 그리고, 재생 내내 우측 자리에 상주 (접힘 아일랜드의 장식용 3바는 걷어 자리를 하나로)
- [x] 시각 값 한 곳으로 — 타일 크기·글자 크기·색·모션을 `Tokens`(순수 숫자) + `DesignTokens`(WPF 타입)에 모아, 한 값을 고치면 모든 화면이 함께 따라옴 (값 사이의 관계는 테스트로 잠금)
- [x] 시각 언어 통일 — 앱 타일(이름 첫 글자)·타이포 계층·정착 모션을 알림 · 인박스 · 클립보드 · 볼륨 링 · 비서 카드가 같은 규칙으로
- [x] 알림 인박스 — 5초 뒤 걷힌 Windows 알림을 노치에서 다시 보기 (전역 단축키, 트레이 개수 포함)
- [x] 진행바 드래그 탐색 — 클릭·드래그로 즉시 이동 (AI `media_seek` 도구와 같은 엔진)
- [x] AI 작업 백그라운드 추적 — 지시하면 노치가 접히고, 사고·도구 실행·완료를 노치 알림으로 추적 (실패만 화면으로)
- [x] AI 탭 얼굴 애니메이션 적용 (눈 두 개가 상태를 말한다 — 포팅해 두었던 오브 렌더러는 얼굴과 함께 정리)
- [x] 대기 비용 — 무한 반복 연출(눈의 호흡 · 충전 맥동)이 화면 주사율만큼 돌며 화면 전체를 다시 합성하던 것을 20fps로 내렸다 (실측: 앱이 노는 동안 코어 1개의 24% → 7~14%)
- [x] 진행 알림이 턴이 끝나도 걷히지 않던 문제 — Esc로 취소한 뒤 노치가 "생각 중…" 카드에 붙잡히던 자리
- [x] 종료 정리 — 인박스 핫키·트레이 아이콘·도구의 HttpClient까지 정리하고, 닫히는 중 도착한 배경 이벤트가 모달 오류창을 띄우지 않게
- [x] 설정을 적용하면 Ctrl+Shift+V(복사 기록)가 조용히 죽던 핫키 버그 — 이제 적용할 때마다 시작 상태와 견주어 죽은 자리를 로그에 남기고, 진짜 앱을 띄우는 회귀 테스트가 같은 것을 밖에서 확인한다
- [x] Pretendard 폰트 번들
- [x] 다중 모니터 대응 — 노치가 앉을 화면을 고르고(주 모니터 자동/특정 디스플레이), 주 모니터가 (0,0)에 없는 배치에서도 제자리에 앉는다. 디스플레이 구성이 바뀌면 다시 계산하고, 고른 모니터가 빠지면 주 모니터로 물러선다 (선택 규칙은 화면 없는 테스트로 잠금)
- [x] 전용 트레이 아이콘 — 노치 실루엣을 그린 `Assets/topdock.ico`를 실행 파일과 트레이가 함께 쓴다
